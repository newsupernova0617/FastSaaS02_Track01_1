webapp API 사용 보고서

대상: webapp/
작성일: 2026-05-21
목적: webapp이 실제로 어떤 인증 API와 앱 백엔드 API를 사용하는지, 그리고 어떤 화면에서 호출되는지를 정리

환경변수 기반 실제 API + preview fallback 혼합 구조 일부 읽기 화면은 mock fallback 사용

1. 요약

  • webapp은 인증에 Supabase를 사용한다.
  • 앱 데이터는 VITE_API_BASE_URL 아래의 /api/app/* 엔드포인트를 사용한다.
  • 읽기 계열 일부 화면은 live API가 실패하거나 토큰이 없으면 mock-data.ts로 fallback 한다.
  • 쓰기 계열 작업은 fallback 없이 실제 백엔드만 사용한다.

2. 환경변수와 베이스 경로

키 용도 사용 위치

5. preview fallback이 있는 읽기 화면

아래 함수들은 live API를 먼저 시도하고, 인증 토큰이 없거나 401/403이면 mock-data.ts 응답으로 대체한다.

6. 코드 구조 해석

  • preview-api.ts는 이름과 달리 실제 백엔드 호출 코드도 같이 가진다.
  • mock-data.ts는 읽기 화면의 preview/demo 데이터를 제공한다.
  • main.tsx는 쓰기 API와 세션/리포트 관리 API를 직접 호출한다.
  • lib/query.ts는 읽기 화면 쿼리 옵션을 만들고, 여기서 preview 함수들이 연결된다.
  • sw.ts는 quick entry 알림의 inline reply를 위해 /api/app/push/reply를 직접 호출한다.

7. 정리

  • 실제 백엔드가 이미 있다면, 제거 후보는 mock-data.ts와 preview fallback 로직이다.
  • 하지만 preview-api.ts 전체는 삭제 대상이 아니라, 실제 API 계층으로 이름을 정리할 대상에 가깝다.
  • 읽기 화면도 모두 실백엔드만 쓰게 바꾸려면 fetch*Preview() 계열 사용처부터 정리해야 한다.
