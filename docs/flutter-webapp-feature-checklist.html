Flutter → Webapp 기능 흡수 체크리스트

판정: 전부 흡수되지 않았습니다.
핵심 거래/달력/통계/월간 리포트/세션 관리 쪽은 webapp으로 많이 옮겼지만, 온보딩, 도움말, 문의, AI 허브, 리포트 상세 관리, 일부 로그인 UX, 그리고 Flutter 전용 네이티브 기능은 아직 남아 있습니다.

완료에 가까움 부분 흡수 미흡수 / 의도적 제외

흡수된 핵심

기록, 달력, 통계, 월간 리포트 생성/조회, 세션 CRUD, 프로필/로그아웃 기본 표시, 그리고 guest fallback 기반 PWA 셸은 webapp 쪽에 들어와 있습니다.

남은 큰 구간

Flutter의 전용 화면들 중 onboarding, help, contact, AI hub, report detail, settings의 1:1 대응은 아직 부족합니다. 로그인 UX도 OAuth 중심 Flutter 화면과 동일하진 않습니다.

의도적 차이

webapp은 Flutter를 그대로 복제하기보다, web-first PWA로 재구성했습니다. 따라서 ads, foreground service, native overlay, quick entry 같은 네이티브 전용 기능은 그대로 이식 대상이 아닙니다.

기능별 상태

Flutter 기능 상태 webapp 대응 / 메모
login_page 부분 흡수 webapp에 로그인 패널은 있지만 Flutter의 Google/Kakao OAuth 플로우와 동일하진 않음.
onboarding_page 미흡수 webapp에 별도 온보딩 시퀀스는 없다.
home_page 부분 흡수 webapp 홈은 채팅/세션 중심으로 재구성되어 Flutter 대시보드와 1:1 동일하지 않음.
ai_hub_page 미흡수 별도 AI 허브 화면은 없다. 일부 기능은 홈/검색/월간 리포트로 분산됨.
record_page 흡수 완료 거래 입력, 조회, 삭제를 webapp의 record 탭에서 처리한다.
calendar_page 흡수 완료 월간 달력, 날짜 선택, 해당 일 거래 목록이 webapp에 있다.
stats_page 흡수 완료 월별 통계, 카테고리 분포, 최근 리포트 표시가 webapp에 있다.
monthly_report_page 흡수 완료 월간/주간 리포트 생성, 현재 리포트 보기, 저장된 리포트 목록이 있다.
report_detail_page 부분 흡수 리포트 데이터는 조회되지만 Flutter처럼 상세 저장/이름변경/삭제 UX가 완전히 동일하진 않다.
chat_screen + session_sidebar 부분 흡수 세션 CRUD와 대화 입력은 있지만, Flutter의 전용 풀스크린 채팅 + 사이드바 경험과는 다르다.
settings_page 부분 흡수 프로필/구독 정보는 보이지만 독립 설정 페이지는 없다.
help_page 미흡수 별도 도움말 페이지 없음.
contact_page 미흡수 문의/피드백 폼은 webapp에 없다.
report naming dialog 미흡수 Flutter의 리포트 이름 지정 대화상자 대응 UI는 아직 없다.
login/logout/profile basics 흡수 완료 Supabase 세션, 로그아웃, 프로필/구독 상태 표시는 webapp에서 지원한다.
ads / interstitial / banner 미흡수 PWA 방향상 기본적으로 제외. Flutter native 광고와 동일한 구현은 없다.
foreground service / overlay / quick entry 미흡수 네이티브 전용 기능이라 webapp에 직접 대응되지 않는다.
auto report scheduling 부분 흡수 리포트 생성 API는 있지만 Flutter의 백그라운드 자동 스케줄러와 동일한 체계는 아니다.

다음 체크리스트

  • 전용 채팅 화면 정리 webapp의 홈 중심 채팅을 Flutter의 full-screen chat + session sidebar 경험에 더 가깝게 맞출지 결정한다.
  • 리포트 상세 화면 보강 리포트 저장, 이름 변경, 삭제, 상세 진입을 webapp UI로 흡수한다.
  • 로그인 UX 통일 Flutter의 OAuth 중심 로그인과 webapp의 현재 Supabase 로그인 패널을 하나의 정책으로 정리한다.
  • 온보딩 / 도움말 / 문의 별도 페이지를 webapp에 유지할지, 랜딩 페이지나 지원 문서로 넘길지 결정한다.
  • 설정 페이지 여부 결정 프로필, 구독, 로그아웃, 약관, 계정 관리가 별도 settings 화면으로 필요한지 검토한다.
  • 네이티브 전용 기능 제외 확정 ads, foreground service, overlay, quick entry 같은 Flutter 전용 기능을 PWA에서 어떤 수준까지 대체할지 확정한다.
  • 최종 흡수 판정 실데이터 런타임 검증이 끝난 뒤 Flutter를 유지할지, 레거시로 둘지, 제거할지 결론을 낸다.

참조 범위: flutter_app/lib/routes/app_router.dart, flutter_app/lib/features/*, webapp/src/*. 이 체크리스트는 정적 코드 기준의 비교 결과이며, 실데이터 런타임 검증은 별도로 남아 있다.
