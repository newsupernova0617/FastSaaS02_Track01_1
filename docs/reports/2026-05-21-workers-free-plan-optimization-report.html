Cloudflare Workers Free Plan Optimization

Workers Free plan에서 함수 사용량을 줄이고, 10ms CPU 제약에서 멀어지는 방법

이 보고서는 Cloudflare 공식 문서의 현재 제한값을 기준으로, 어떤 요청을 Workers가 처리해야 하고 어떤 요청은 Workers 밖으로 빼야 하는지 정리합니다. 핵심은 “Workers를 얇게 유지하고, 무거운 작업은 다른 계층으로 이동”하는 것입니다.

핵심 전략

공식 제한

Cloudflare 공식 문서 기준, Free plan에서 가장 중요한 제약은 일일 요청 수와 요청당 CPU 시간입니다.

일일 요청
100k

UTC 기준 자정에 리셋

정적 자산은 Worker 코드를 안 타면 무료

네트워크 대기 시간은 CPU 시간에 포함되지 않습니다. 즉, `fetch()` 자체보다 Workers 내부에서 얼마나 많은 계산, 파싱, 직렬화, 검증을 하느냐가 10ms 한계에 더 직접적입니다.

함수 사용량 절약

Workers invocation 자체를 줄이는 방법은 “아예 Worker를 안 타게 만들기”가 가장 효과적입니다.

정적 자산 분리

  • HTML, JS, 이미지, 아이콘은 가능하면 static asset으로 서빙
  • 정적 자산 매칭 요청은 Worker 코드 실행 없이 응답 가능
  • 대시보드/정적 페이지는 `backend`가 아니라 Pages/asset 경로로 분리

캐시 우선

  • 자주 읽는 GET 응답은 edge cache 활용
  • 월간 리포트, 홈 요약, 부트스트랩 같은 응답은 TTL 캐시 후보
  • 같은 사용자/같은 월/같은 기간은 재생성보다 재사용이 낫다

요청 통합

  • 여러 작은 요청을 하나의 API로 합치기
  • 폴링 대신 이벤트 기반 갱신 사용
  • 클라이언트에서 같은 데이터를 반복 조회하지 않기

중복 라우팅 제거

  • Workers에서 일반 API와 AI API를 같은 경로로 중복 처리하지 않기
  • 현재 구조처럼 직접 AI 경로만 VPS로 보내면 Workers 호출 비용을 제한 가능

10ms CPU에서 멀어지는 법

CPU 시간을 줄이려면 Workers에서 수행하는 계산량을 줄이고, 무거운 연산을 외부로 빼야 합니다.

오프로드

  • LLM 호출, 리포트 생성, RAG, 큰 JSON 분석은 `backend-vps`로 이동
  • Workers는 인증과 라우팅, 가벼운 검증만 담당
  • 이렇게 하면 Workers는 10ms 안쪽의 “얇은 게이트웨이” 역할만 수행

스트리밍

  • 큰 request/response body는 통째로 버퍼링하지 않기
  • Cloudflare 문서도 `TransformStream` 또는 `node:stream` 사용을 권장
  • 필요 없는 응답 본문은 `response.body.cancel()`로 메모리 정리

파싱 축소

  • 큰 배열 정렬, 다중 그룹 집계, 문자열 재가공을 Worker 안에서 최소화
  • 응답 직전의 후처리를 줄이고, 저장/집계는 VPS나 DB 쿼리로 넘기기

플랜 전환

  • Workers Paid로 가면 CPU 제한이 5분으로 올라감
  • 하지만 Free plan을 유지하려면 구조적으로 10ms 이내에 머무는 설계가 필요
Free plan에서 “10ms 제약에서 멀어진다”는 말은, 사실상 Worker 내부 계산을 줄이거나 아예 다른 런타임으로 옮기는 뜻입니다. 네트워크 대기는 CPU에 안 잡히지만, Worker 안에서의 계산은 그대로 제한됩니다.

현재 아키텍처에 맞는 권장안

현재 저장소 구조에서는 `backend`를 얇게 만들고, 직접 AI 기능은 `backend-vps`에 두는 편이 맞습니다.

flowchart LR FE[webapp / frontend] W[backend
Cloudflare Workers] V[backend-vps
Node VPS] DB[(Turso)] AI[External AI API] FE --> W W -->|lightweight general API| DB W -->|direct AI routes only| V V --> DB V --> AI

Workers에 남길 것

  • JWT 인증
  • 일반 CRUD / 조회 API
  • 캐시 가능한 GET 응답
  • 정적 자산 서빙

VPS로 뺄 것

  • LLM 호출
  • 리포트 생성
  • 세션 메시지 AI 처리
  • 큰 컨텍스트 조합 / 후처리

실행 체크리스트

아래 순서대로 적용하면 Free plan 비용과 CPU 리스크를 동시에 줄일 수 있습니다.

1. Worker를 얇게 유지

  • 프록시와 검증만 남기고 무거운 로직 제거
  • 가능한 모든 응답은 짧고 결정적으로 만들기

2. 정적/캐시 분리

  • 정적 자산은 Worker를 타지 않게 배치
  • 자주 쓰는 GET은 캐시

3. AI 전용 백엔드 유지

  • 직접 AI 경로만 `backend-vps`로 보냄
  • AI 호출, 리포트 생성, 무거운 파싱을 VPS에서 처리

4. 플랜 선택

  • Free plan을 유지할 거면 구조적으로 10ms 이내 유지
  • CPU 여유가 필요하면 Workers Paid 검토
