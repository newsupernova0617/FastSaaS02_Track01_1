backend-vps 구성 보고서

`backend-vps` 패키지에 어떤 파일이 있고, 각각 어떤 역할을 맡는지 정리한 보고서

현재 `backend-vps`는 VPS 전용 배포 단위입니다. 직접 AI 통신이 필요한 경로만 처리하도록 구성되어 있고, `backend/`와 독립적으로 배포할 수 있도록 자체 `src/` 구조를 보유합니다.

배포 대상
`backend-vps/` 단독
런타임
Node.js VPS
기본 포트
8788
역할
직접 AI API 처리

핵심 요약

이 패키지는 직접 AI 통신 경로만 담당하는 얇은 VPS 백엔드이지만, 배포 독립성을 위해 필요한 앱/라우트/서비스 코드를 자체 보유합니다.

폴더 역할

실제로 관리해야 할 파일은 `node_modules`가 아니라 아래 구조입니다.

루트 파일

  • package.json: VPS 실행 스크립트와 의존성
  • tsconfig.json: 독립 타입체크 설정
  • .env.example: VPS 환경 변수 예시
  • README.md: 배포/실행 문서

`src/` 핵심

  • server.ts: Node 서버 엔트리
  • app-vps.ts: VPS 전용 앱 조립
  • runtime/node-env.ts: `.env` 로딩
  • runtime/ai-routing.ts: 직접 AI 라우트 판별

비즈니스 로직

  • routes/: 엔드포인트 정의
  • services/: AI, 리포트, 세션 처리
  • db/: Env 타입, DB 클라이언트, 스키마
  • middleware/, utils/, types/: 공통 보조 레이어

중요 파일

실행 흐름을 이해하려면 아래 파일부터 보면 됩니다.

`src/server.ts`

Node 서버를 띄우고 `vpsApp.fetch(...)`로 요청을 넘깁니다. 기본 포트는 `8788`입니다.

`src/app-vps.ts`

CORS, 로깅, 인증, 직접 AI 라우트 제한, 실제 라우터 연결을 담당합니다.

`src/runtime/node-env.ts`

`.env` 또는 `.dev.vars`에서 VPS 실행용 환경 변수를 읽어 `Env` 객체를 만듭니다.

`src/runtime/ai-routing.ts`

VPS가 허용할 직접 AI 경로를 정규식 기준으로 고정합니다.

`src/routes/`

`ai.ts`, `sessions.ts`, `app.ts`, `reports.ts`, `push.ts`가 직접 AI 관련 엔드포인트를 처리합니다.

`src/services/`

`ai.ts`, `llm.ts`, `ai-report.ts`, `session-message-handler.ts`, `vectorize.ts` 등이 실제 AI 동작을 담당합니다.

직접 AI 경로와 파일 연결

왜 파일 수가 생각보다 많은지 이해하려면, 한 엔드포인트가 서비스 레이어를 얼마나 깊게 타는지 보면 됩니다.

예시 1

POST /api/sessions/:sessionId/messages

  • routes/sessions.ts
  • services/session-message-handler.ts
  • services/ai.ts
  • services/llm.ts
  • services/context.ts
  • services/vectorize.ts

예시 2

POST /api/reports/generate

  • routes/reports.ts
  • services/ai-report.ts
  • services/llm.ts
  • db/schema.ts

예시 3

POST /api/app/push/reply

  • routes/push.ts
  • services/push.ts
  • services/session-message-handler.ts

현재 판단

`backend-vps`는 단순한 한 파일짜리 서버가 아니라, 독립 배포 가능성을 확보하기 위해 필요한 최소 앱 구조를 스스로 갖춘 상태입니다.

좋은 점

  • `backend/`와 배포 경계가 분리됨
  • VPS만 따로 올려도 동작 가능
  • Workers 장애와 AI 통신 장애를 운영상 분리 가능

주의점

  • 현재는 `backend` 소스 일부가 복제된 형태라 장기적으로 동기화 비용이 생김
  • 나중에는 공용 패키지 분리(`backend-core`)가 더 깔끔함
이 보고서는 2026-05-21 기준 `backend-vps`의 실제 파일 구성과 역할을 정리한 HTML 문서입니다. 구현 단위를 빨리 파악하기 위한 문서이며, 이후 공용 패키지 분리 작업의 기준점으로도 쓸 수 있습니다.
