구조 변화

이전 상태와 현재 상태를 비교해서 보는 섹션입니다.

이전 인식

  • backend/ 가 Cloudflare Workers 중심으로 보이던 구조
  • wrangler.jsonc, Workers AI, fetch(request, env, ctx) 엔트리 사용
  • 런타임 설명과 실제 운영 경로가 혼재되어 있었음

현재 기본 구조

  • backend/ 는 Hono 앱을 Node 서버로 띄우는 VPS 경로
  • backend/src/server.ts 가 개발 및 실행 진입점
  • 기본 포트는 8787, 로그에 http://:::8787 로 보일 수 있음

병행 구조

  • backend-cloudflare/ 는 Workers 대안 패키지로 분리
  • 공용 Hono 앱은 재사용하고 런타임만 분기
  • AI 요청은 직접 처리하지 않고 VPS API로 프록시

검증 결과

실행 및 테스트 기준으로 확인된 결과입니다.

통과한 검증

  • cd backend && npm run type-check
  • cd backend && npm run test:llm
  • cd backend && npx vitest run tests/routes/ai.test.ts tests/services/ai-report.test.ts tests/llm-smoke/ai-parse.llm.test.ts
  • cd backend-cloudflare && ../backend/node_modules/.bin/tsc --noEmit -p tsconfig.json

남아 있는 제약

  • 전체 npm test 는 원격 Turso 기반 통합 DB 이슈로 일부 실패
  • 실패 원인은 이번 런타임 전환 자체보다 테스트 환경의 테이블 부재에 가까움
  • 따라서 핵심 변경 경로는 통과했지만, 통합 환경 검증은 별도 보강이 필요

운영 기준

현재 기본 백엔드는 backend/ 이며, Hono 앱을 Node 서버로 띄우는 VPS 구조로 보는 것이 맞습니다.

대안 기준

Cloudflare Workers가 완전히 사라진 것은 아니고, backend-cloudflare/ 로 분리되어 선택지로 남아 있습니다.

AI 처리 기준

Cloudflare 쪽에서 AI를 직접 처리하는 구조가 아니라, AI 관련 라우트만 VPS API로 넘겨 책임을 분리한 상태입니다.
