# 메뉴얼

이 문서는 블로그, 랜딩, Flutter 화면을 찍기 위해 Turso에 넣는 mock data 가이드다.
실제 계정 기준으로 바로 넣을 수 있는 전체 seed는 [docs/demo-seed-user.sql](./demo-seed-user.sql) 에 따로 분리해 두었다.
Drizzle Studio에서는 `BEGIN` / `COMMIT` 없이 이 파일을 그대로 붙여넣어 실행하면 된다.

Turso에 바로 넣을 때는 아래처럼 실행하면 된다.

```bash
turso db shell <database-name> < docs/demo-seed-user.sql
```

웹 콘솔에 붙여넣을 때도 `docs/demo-seed-user.sql` 내용을 그대로 넣으면 된다.
이 파일은 상단에서 기존 데이터를 비우고 `sqlite_sequence`까지 초기화한 뒤, users / transactions / sessions / reports / chat_messages / user_notes 순서로 다시 채운다.

## 먼저 결론

- 실기기 촬영은 필수가 아니다.
- 한 세트 안에서는 Android 또는 iPhone 중 하나로 통일하는 게 좋다.
- mock data는 `입력 -> 저장 -> 결과` 흐름이 자연스럽게 보이도록 넣는다.
- 실제 로그인 계정이 이미 있으면 `demo-alice` 대신 그 계정의 `user.id`를 그대로 쓰는 게 가장 좋다.
- 개발 우회로 백엔드만 볼 거면 `e2e-test-admin-token` + `e2e-test-admin` 조합을 쓸 수 있다.
- 화면별 핵심 테이블은 아래처럼 잡으면 된다.

| 화면 | 주 테이블 | 목적 |
|---|---|---|
| 홈 / 달력 / 통계 | `transactions` | 지출, 수입, 월별 합계, 차트 |
| 채팅 | `sessions`, `chat_messages` | 기록, 검색, 리포트 액션 화면 |
| 리포트 | `reports` | 상세 리포트 탭 / 리포트 상세 화면 |
| AI 문맥 보강 | `user_notes` | AI 답변을 조금 더 자연스럽게 보강 |

## 추천 데이터 구성

### 필수

- `users` 1명
- `transactions` 30여 개
- `sessions` 3개
- `chat_messages` 6개
- `reports` 3개
- `user_notes` 2개

### 선택

- `users` 1명 추가
- `transactions` 2개 추가

Bob 데이터는 소유권 분리 확인용이다. 스크린샷만 만들면 생략해도 된다.

## 실무 추천

- 스크린샷용이면 `demo-alice`만으로 충분하다.
- 통계와 리포트까지 자연스럽게 보이려면 3월 + 4월 데이터가 같이 있어야 한다.
- 채팅 화면은 `sessions`와 `chat_messages`가 핵심이다.
- 리포트 화면은 `reports`만 있어도 바로 채울 수 있다.
- AI 문맥은 `user_notes`를 추가하면 조금 더 그럴듯해진다.

원하면 다음 단계로 이 내용을 `seed.sql`로 분리해서 바로 실행 가능한 형태로 정리해줄 수 있다.
